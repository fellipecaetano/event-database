# Grilling session — 27 July 2026

A compaction of the session that produced [CONTEXT.md](../CONTEXT.md), the
[ADRs](./adr), [principles.md](./principles.md) and
[open-questions.md](./open-questions.md).

Those documents record *what* was decided. This one records *how* — the order questions
were taken in, which answers reversed earlier ones, and where the framing had to be redone.
It exists so a later session can argue with the reasoning rather than only inherit the
conclusions.

The project began as an empty directory named `event-database`. Every fact below came from
the session or from research during it; nothing was assumed from a prior codebase.

---

## Setting the frame

**What is it?** Not an event store or a telemetry sink — a catalogue *of* real-world events.
That made identity and time the hard problems rather than ordering and replay.

**Who for?** Personal tool now, public aggregator later, with **data quality as the
differentiator**. This was the single most consequential answer of the session: it meant
provenance and identity had to be first-class from day one rather than added when users
arrived.

**Scope?** Music events, São Paulo first, other Brazilian cities later. Chosen against
broader alternatives on the grounds that quality is a function of source density per slice —
cross-checking is only possible where several sources overlap.

**Atomic unit?** The door model: one venue, one date or session. Lollapalooza is three
Events; an early and a late show are two. Chosen over per-performance, per-ticket and
per-promoted-happening because it is the unit people mean by "what's on tonight" and it
survives ticketing and lineup changes.

## The architecture, in the order it was built

**Language** → English domain model, Brazilian terms kept untranslated where translating
flattens meaning (*baile funk* is not "a party"). → ADR 0001

**Provenance** → An append-only Observation log, with Events as projections over it. Chosen
over updating rows in place because quality claims must be defensible field by field, and
unrecorded history cannot be reconstructed. → ADR 0002

**Identity** → The first attempt at this question was rejected and re-asked with much more
depth. Outcome: Events own intrinsic IDs; matching generates scored candidates and records
reversible Match judgements; human verdicts outrank machine ones. The decisive argument was
that on day one it behaves exactly like manual curation — the difference is that the manual
work *compounds* into labelled data rather than evaporating. → ADR 0003

**Field conflicts** → Per-field Source trust, recency breaking ties, Override beating
everything. No ADR: because Events are projections, resolution logic is a pure function that
can be changed and re-run, so it fails the "hard to reverse" bar.

**Time** → Local wall time plus IANA zone, instant derived. Start means doors, with Showtime
kept separately, because "happening now" should be true from the moment you could be inside.

**Lifecycle** → Explicit Status; a vanished listing is evidence, never proof. Here the user
reframed the whole product: the log *"allows us to be more probabilistic and less
deterministic when rendering that data."* That turned a mechanism into a stance — the
catalogue knows how sure it is, and competitors render guesses as facts. → ADR 0004

**Sources** → Research established that **no public catalogue API exists**: Sympla's public
API is scoped to the caller's own events, Eventbrite withdrew public event search in 2019,
Resident Advisor has no official API. Every route is scraping, a partner deal, a paid
intermediary, or manual entry.

**The vision correction** → The user's actual intent was raw documents — Instagram posts,
newsletters, spreadsheets — read by an LLM, not structured feeds. This largely neutralised
the missing-API problem and reshaped ingestion: collectors *acquire documents*, extraction is
a separate stage. Documents may describe many events or none, carry their own timestamps
(without which "nesta sexta" is meaningless), and hallucination becomes a first-class risk.

**Ingestion** → Manual gathering, LLM extraction in an interactive session, no programmatic
API spend — behind one contract a future scraper can call. → ADR 0005

**Evidence** → Source text retained; flyers, images and HTML not. The user initially proposed
keeping nothing beneath the log; the deciding argument was that the Observation schema at
extraction time otherwise permanently caps what can ever be known from a Document.

**Storage** → Append-only JSONL, partitioned by period, with everything else derived. The
user's constraint — the format must let actors other than LLMs append — is what selected
JSONL. → ADR 0006

## Detailed grilling, by area

**Venues.** Name and city required, city from ingest context where unstated; address and
working hours optional. Identity is the *operation*, not the address — renaming keeps the
Venue, a new club at an old address does not. Closure is recorded when observed but nothing
may depend on it. Duplicates are prevented at creation first, merged after the fact when they
slip through.

**Observations.** One Observation is everything a Document says about one subject, as read
on one occasion — the build pivots readings into per-field claims, so nothing is lost against
a fine-grained design. Observations carry a *subject*, so venue facts get the same machinery
as event facts. A validated core plus a keyed extras bag; promoting an extra is a build-time
transform, never a re-extraction. Re-readings are ranked by Extractor trust, and confidence
deduplicates by Document — two readings of one post are one piece of evidence.

**Ingest.** A CLI with logic in a core library, so MCP or a scraper becomes another thin
adapter. It validates but cannot gate, since the format is deliberately open, so a separate
verify pass sweeps the log. Every claim carries the Span of text supporting it, mechanically
checked — which turns hallucination detection into string matching. → ADR 0007

**Confidence.** Per fact, with existence among those facts. Expressed as three ordered tiers
— Validated, Corroborated, Single-source — rather than a number, because every signal that
moves it is categorical and calibrating a score would need ground truth nobody has. Source
trust attaches to a Source's *kind*. Calibration is passive from Overrides now, stratified
random Audits later.

**Matching.** Date ±1 day blocking, because tens of comparisons a night makes anything
cleverer pointless. Auto-linking must demonstrate 99% precision on recorded decisions, since
a wrong merge silently deletes a real event while a missed match only shows a visible
duplicate. The review queue is derived and ordered by impact.

**Time details.** Date-only Events take an estimated Start from the Venue's opening hours,
mirroring the Bound. Multi-day is mostly a non-issue under the door model; date ranges expand
into one Event per day as derived claims.

**Scope.** Ticket link and from-price in core, structure in extras, prices explicitly low
priority. Genre captured verbatim with no taxonomy. City expansion is opportunistic — the
architecture has no city gate.

## Reversals

Six decisions changed during the session. They are listed because the reasoning that
overturned them is more useful than the conclusions.

1. **The night field** — recommended, then deferred. Once the user named "happening now" and
   sorting as priorities, it became clear night serves neither; it is a grouping concept.
2. **Series** — recommended, then deferred. The matcher argument was overstated: date-based
   blocking already keeps weekly siblings apart, so the benefit was mostly a browsing feature.
3. **The end-time prior** — the learned "typical duration per venue" was circular, since it
   could only learn from the published ends that are precisely what is missing. The user's
   suggestion of working hours replaced it, and reframed End as a **Bound** rather than an
   estimated point.
4. **Provisional venues** — recommended, rejected by the user in favour of raw names, then
   reinstated after re-assessment. Two arguments turned it: raw names impose a permanent
   union type on every consumer, and a venue held with low Confidence is not a new concept
   under ADR 0004, it is an existing one applied consistently.
5. **"The authoritative list's guarantee moves into a flag"** — withdrawn. The guarantee stays
   in recorded Validations; "Provisional" is derived, not stored.
6. **SQLite in ADRs 0005 and 0006** — over-committed. The user clarified that "the database is
   the product" meant the data and the log format, not a literal relational database. The
   derived form now waits for an application to have an opinion.

## Where the framing failed

Points where a question had to be withdrawn or re-asked. Useful signal about how to pitch
future sessions.

- **Identity**, first attempt — rejected outright; needed the full mechanism (blocking,
  thresholds, recorded decisions, merge and split) before the choice was meaningful.
- **"Explicit night"** — unclear twice. Resolved only by a worked table of examples and by
  admitting it buys nothing for the stated priorities.
- **"How many states?"** for unknowns — the user rejected the framing entirely, correctly.
  There was no state machine, only whether a key is present. The real question was whether
  "a confirmar" is worth capturing.
- **Re-extraction** — "why option 1 over option 3" exposed a glib option description. The
  honest answer needed two distinct readings of option 3, one of which was legitimate.
- **Random audits** — the mechanics had to be spelled out before the choice could be made.
- **Candidate generation** — the user asked what it was for; it is arguably below the level
  worth grilling at this stage.
- **The relational schema** — rejected as premature, and correctly so. It depends on an
  application that does not exist.

## What the user contributed that changed the design

Not answers to questions, but reframings that redirected it:

- *"The Observation log is what truly makes the solution shine ... allows us to be more
  probabilistic and less deterministic."* → ADR 0004, and the product position.
- *"I want the LLM to get progressively smarter as I validate more and more of its work."* →
  Validations as recorded acts, Aliases accumulating, thresholds derived from decisions.
- *"I'm realizing that the Observation log is the source of truth for everything."* →
  Principle 1, and the dissolution of the separate curated venue file.
- **Working hours on a Venue** → exposed the circular duration prior; produced the Bound.
- *"As long as the file format allows other actors to append."* → JSONL specifically.
- *"The most valuable product is the database itself"*, later clarified as the data and its
  format → the derived form deferred entirely.
