Query the catalogue

Your first win: read upcoming Event titles without knowing anything about JSONL, verification, Fold rules, or Redirects.

Mental model: the log is the source of truth; openCatalogue gives you one immutable Projection at one explicit instant.

1. Choose the root interface

You only need Event data. Import the ordinary interface, not review or maintenance. 

import { openCatalogue } from "@event-database/catalogue";

const catalogue = await openCatalogue({
  repositoryRoot: process.cwd(),
  at: new Date("2026-08-17T12:00:00Z"),
});

The explicit clock is part of the query. The same log, rules, and clock produce the same Projection. See ADR 0006.

2. Read typed facts without hiding uncertainty

for (const event of catalogue.events.all()) {
  const title = event.facts.title;
  if (title?.state === "known") {
    console.log(title.value, title.confidence);
  }
}

Do not write event.facts.title?.value ?? "Unknown": an absent fact and a stated unknown are different domain claims. Narrow on state.

3. Use identity correctly

const event = catalogue.events.get(requestedEventId);

if (event !== undefined) {
  console.log(event.id); // canonical surviving ID
}

get() follows recorded Redirects. Callers should not rebuild merge logic or scan arrays themselves.

4. Know the two escape hatches

event.rawFact("price_from"); // persisted snake_case key
event.extras.get("age_restriction");

rawFact() preserves malformed Override values that cannot appear in a typed property. extras keeps unpromoted observed facts separate from the core vocabulary.

Import the root interface because this is an ordinary read. Do not serialize the Event directly: it contains internal IDs and provenance. Build a separate public-safe projection, following packages/catalogue-site.
