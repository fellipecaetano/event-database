# Mission: Use the catalogue package safely

## Why
Build new catalogue consumers without reimplementing storage, verification, Fold, identity, or
uncertainty rules, and without leaking internal evidence into public output.

## Success looks like
- Choose the root, review, or maintenance interface for a concrete task.
- Open a reproducible catalogue and correctly read known, unknown, and malformed facts.
- Add a package consumer while preserving dependency direction and publication safety.

## Constraints
- Learn through this repository's actual interfaces and domain language.
- Keep examples short enough to run and modify immediately.

## Out of scope
- Redesigning Fold policy, record schemas, matching, or remote storage.
